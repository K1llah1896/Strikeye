# Design: 音轨混音

## Context

合成管线已经有一条 BGM 通路（`mixBGM`：循环 BGM + 淡入淡出 + `amix normalize=0`）。语音/解说音轨与 BGM 的区别是：要能对齐到具体时刻（偏移）、要能按轨静音、要能在不重新编码视频的前提下重混。

## Decisions

1. **在 BGM 之后混，而不是在 `amix` 里一次混完**：偏移是相对成片时间线的。先把片段拼成成片、混完 BGM，再叠加语音轨，语义最直观；缺点是两次编码音频，但音频编码成本相对视频可忽略，且视频始终 `-c:v copy`。
2. **负偏移 = 裁头**：`adelay` 无法表达负延迟，但"音轨比画面早开始"是真实场景（麦克风先开）。用 `atrim=start=|offset|` 裁掉头部再归零，等效于把音轨整体前移。
3. **`@` 只在后面跟数字时才当分隔符**：文件名里出现 `@` 很常见（`comms@team.wav`），因此 `looksNumeric` 判定；同时避免把 Windows 盘符 `C:` 误当音量分隔符（音量分隔符只在 `@` 之后查找）。
4. **音量上限 4 且 0 视为默认 1.0**：0 在 JSON 里是"未设置"的零值，若真按 0 处理会让所有未设置音量的轨静音；真正的静音交给 `Mute`。
5. **调用方错误要显式报错**：所有轨道都被静音时 `MixAudioTracks` 返回错误而非静默输出原片——静默失败在批量渲染里极难发现。
6. **独占音频导出走中间 mp4**：`-c:a aac` 直接写 `.m4a` 时 ffmpeg 会拒绝"同文件进出"，因此 CLI 先混到临时 mp4 再抽音频。

## Risks

- 两次音频编码有轻微代际损失；若需要母带质量可后续改为单次 `filter_complex`。
- `amix normalize=0` 保留原始增益，多轨叠加可能削波；音量值由用户控制，文档提示总和建议 ≤1.0。
