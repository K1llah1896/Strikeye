# 设计

## 决策

**为什么强制 TTL=0 而不是复用 30 天**：用户点"刷新头像"的语义就是"忽略缓存重取"。缓存命中判断已在 `avatars.Path` 层，TTL 传 0 即跳过新鲜度检查。

**为什么统计"新下载/已缓存"用路径是否变化**：`Client.Fetch` 返回路径，但下载与缓存命中都返回同一路径；用 `Path()` 在调用前探测是否已存在，可以区分两者而不改既有 API。

**为什么并发上限是整队串行**：10 个头像、每个一个 XML + 一个 PNG，串行在 2 分钟超时内足够，且避免被 Steam 限速。

## 风险

- 没有失败计数展示：失败的选手只是保持旧头像，用户看不到"3 个没取到"。后续若需要可加 `Failed []string`。
- 刷新是整队，不能单独刷某个人（当前 UI 没有选中态）。
