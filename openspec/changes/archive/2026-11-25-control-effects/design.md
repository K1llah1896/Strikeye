# Design: Smoke- and Fire-Aware Control

## 为什么烟雾与火焰处理不同

- 烟雾在 CS2 里**挡视线不挡人**：选手可以走进烟里，只是看不到外面。因此烟只影响"这个区域现在归谁"的判断——它在统计上既不是 T 的也不是 CT 的，直接记为遮挡。
- 火焰**既挡视线也挡人**：走进火里会掉血，正常推进不会穿火。因此火除了解除归属，还要从可达图里摘掉节点，否则 CT 会"穿过"一道火墙到达对面。

## 实现

`activeEffects(rd, tick, centroids, cfg)` 每个采样 tick 返回两个集合：

1. `blocked`：烟雾球 + 火焰凸包覆盖的区域（用于跳过归属）；
2. `cut`：火焰凸包覆盖的区域（传给 `dijkstra` 作为不可展开节点）。

- 烟雾判定用球形：XY 距离 ≤ `SmokeRadius`，`|dz| ≤ SmokeRadius`。用 Z 容差是为了让上下层同 XY 的区域不会被同一颗烟误伤（比如 dust2 的 B 洞与上隧道）。
- 火焰凸包用 2D 射线法（`pointInHull`），因为 `InfernoEffect.Hull` 本身就是投影后的多边形；上下层不区分，这是已知简化，写进了报告。
- 时间窗用 `StartTick ≤ tick ≤ EndTick`；`EndTick <= 0` 视为"到回合结束仍有效"，避免脏数据把效果永久关掉。

## 复杂度

每个采样是 O(区域数 × 生效效果数)。dust2 2242 区域、峰值 5 颗烟 + 2 道火，409 采样总耗时 0.7 秒，仍在标签页后台可接受范围内。区域质心在 `Build` 开始处预计算一次，避免重复 `Centroid()`。

## 对照验证

`--effects=false` 保留旧行为，用于回答"这条曲线里道具到底改变了多少"。dust2 同一场：整场平均净值从 +0.20 降到 +0.156，平均 16.9 个区域被遮挡（峰值 111，对应 B 洞一道大火）。
