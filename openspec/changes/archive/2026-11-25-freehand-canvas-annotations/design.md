# Design: 2D 雷达自由笔刷

## Context

`Radar2DCanvas` 把帧渲染到 `ui.Bitmap`（gg + 雷达底图），并用 `ui.Image` 贴到界面上。mygo 元素可以获得指针位置，但画布本身是位图，没有内建的"绘图事件"，所以要自己把指针采样变成笔迹。

## Decisions

1. **归一化坐标**：存 `[0,1]` 而不是像素或世界坐标。像素会随窗口尺寸失效；世界坐标要求调用方知道地图投影参数，而笔迹是"在雷达图上画的"，图像空间才是它的自然坐标系。
2. **每帧采样 + 最小步长 0.004**：指针帧频率高，全部记录会让一条线变成上千点；距离阈值把典型一笔压到几十点，肉眼无差别，JSON 也小。
3. **释放时落库，绘制中只在内存**：拖动过程每帧都会回调，逐点写库会把 SQLite 打满；松开主键时一次写入整条笔迹。释放判定用"本帧 `Pressed()` 为假但是笔刷仍开"，配合 `PressedOutside()` 兼容拖出画布。
4. **回放渲染后叠加**：笔迹画在帧图像上（`drawStrokesLocked` 放在 `drawPinsLocked` 之后），所以拖动帧时笔迹跟着内容一起重绘，不需要单独的图层。
5. **回合绑定**：`round_number = 0` 表示整场通用（战术原则），具体回合号表示该回合专用（具体执行）。查询时两者都取，符合"先看通则再看执行"的阅读顺序。
6. **不引入撤销栈的第一版**：清除按回合整批删除，够用；单条删除留给 `strokes --clear` 与后续迭代。

## Risks

- 高频拖动在低端机器上可能跟不上帧率，笔迹会略稀疏（阈值内插不做）；观感影响有限。
- 归一化坐标假设雷达图为正方形且满幅，这是画布既有约束。
