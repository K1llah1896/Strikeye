# Design: 对阵矩阵与选手趋势

## Decisions

1. **归一化方向而不是要求调用方传对顺序**：`demos` 里同一组对阵的 `team_a`/`team_b` 会随 demo 源变化，`Build` 按队名匹配后翻转比分，保证 `wins_a`/`rounds_a` 始终指第一支队。队名比较用 `EqualFold`，但输出保留调用方传入的大小写。
2. **只算 `parsed` 场次**：未解析的 demo 没有比分与回放，算进来会让战绩失真。
3. **分图聚合 + 最近交手**：教练需要"图上强项"和"近期状态"两种粒度；`Recent` 按 `match_date` 降序、同日期按 demo id 降序，缺失日期排在最后（空字符串排序天然靠前，故用 `>` 比较而非 `<`）。
4. **趋势用现有 `match_players` 行**，不重算指标：逐场 Rating/ADR 已是解析产物，趋势只需按日期排序并把 `team_a`/`team_b` 翻译成对手名与胜负。
5. **CSV 列固定**：`trends` 的列顺序与 `player_<steamid>_matches.csv` 对齐，便于同一份表格里纵向拼接。

## Risks

- 同一队在不同 demo 里队名写法不一致（大小写/缩写）时不会被识别为同一支队——这是有意为之，避免把不同队合并。
- 日期缺失的历史 demo 在趋势图里会挤在最前面，属于数据质量问题而非逻辑问题。
