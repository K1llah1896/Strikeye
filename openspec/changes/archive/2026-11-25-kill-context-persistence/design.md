# 设计

## 决策

**为什么按需落库而不是解析时入库**：解析阶段几何数据不一定就绪（用户可能先解析后补下载 `.tri`），把几何依赖塞进解析会让"没图"变成"数据缺失"。由 `killctx --store` 显式触发，语义清晰：想查询就先算一次。

**为什么主键含 `victim_slot`**：同一 tick 可能有多名受害者（例如一个闪光后的连锁死亡），只按 `(demo,demo,round,tick)` 会丢行。

**为什么存位置而不只存距离**：SQL 里想画点、想按区域聚合都需要坐标；重读 `.cs2rpl` 的成本远高于多存 6 个 REAL。

**为什么 `Totals` 在 SQL 里聚合**：几十万行时不要在 Go 里遍历；顺带让 SQL 控制台的用户能看到同样口径。

## 风险

- `weapon` 依赖 ±64 tick 的最近一发，榴弹/刀杀可能推断为空字符串（导出里表现为空列）。
- 表随 demo 数量线性增长（每场约 130–250 行），暂不做清理策略。
