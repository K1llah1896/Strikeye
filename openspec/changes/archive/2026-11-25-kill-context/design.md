# Design: Kill Context

## 眼位与胸口的取点

- 击杀者眼位 = 击杀位置 + 64（CS2 站立眼高）。
- 受害者胸口 = 阵亡位置 + 45。
- 两点连线交给 `mapgeom.Tracer.IsOccluded`，它带 1e-4 端点容差，避免贴墙误判。

不用回放帧里选手的实时朝向：`ReplayDeathEvent` 已经存了击杀瞬间双方坐标，且帧采样是 32Hz，用帧会引入最多 31ms 的位置误差。

## 烟雾判定

对每颗在击杀 tick 生效的烟，算线段到"烟心 + 32（烟球中心略高于地面）"的最短距离，小于 144 即判为穿烟。

- 用线段而不是射线：烟在两人之间才挡视线，越过受害者的烟不影响这一枪。
- 与 demoinfocs 的 `ThroughSmoke` 标志互补：官方标志来自引擎判定，本字段是几何复核；两者不一致时以引擎为准，几何列只做参考（UI 上以"·烟"后缀标出）。

## 为什么单独成包而不塞进 parser

击杀几何是**查询**而不是**事实**：同一份回放，有几何数据时能算视线，没有时只有距离。把它放在解析之外，意味着：

- 旧库不需要重解析就能补上这一层；
- 换成更精确的几何（例如带材质的 `.tri`）不用动解析器；
- `killctx` 的测试可以用几十行的假回放，不必造二进制 demo。

## 已知偏差

- 位置来自击杀事件，长距离击杀时引擎上报的射手坐标可能滞后一帧，极端情况下距离会偏大（实测 dust2 最远 1413 单位，合理）。
- 不做开镜/闪光修正；这两项在报告的"可见性修正"里单列。
