# Design: Kill Optics and Line-up Impact

## 角度怎么算

回放帧里每个选手带 `Yaw`（度，0 = +X，逆时针为正），来源是 demoinfocs 的 `Player.ViewDirectionX()`——名字有误导性，它返回的是眼角的 Y 分量（yaw），不是视线向量的 X 分量。

```
view   = (cos(yaw), sin(yaw))
target = normalize(victim.xy − killer.xy)
aim_off = acos(clamp(dot(view, target), −1, 1))
```

只用 XY 平面：俯仰角对"是否看向对方"没有意义，而且爆头线本来就带俯仰。

## 为什么 `fov_pct` 几乎是 100%

击杀要求准星压在目标身上，所以 `in_fov` 基本恒真——它的作用是**校验回放 yaw 的可信度**：如果某一版数据里 `fov_pct` 明显低于 90%，说明 yaw 字段坏了（我们确实踩过这个坑：把 `ViewDirectionY()`（俯仰角）当成 yaw 用，结果全员"背身"）。

真正有信息量的是：

- `ambush_pct`：受害者没看向击杀者，属于被绕后/被抓 timing；
- `blind_kills`：击杀者在闪光状态下完成击杀（含自闪进点）；
- `victim_blind`：单条击杀上的"对方看不见你"。

## 半视角取 53°

CS2 默认 90° 垂直 FOV，16:9 下水平约 106°，半角 53°。开镜会收窄到 40° 左右，但回放不记录是否开镜，所以统一用腰射值，并在 `Config` 里留了可调项。宁可把边缘情况算作"在视野内"，也不要漏判。

## 致盲阈值 0.1 秒

`m_flFlashDuration` 是剩余致盲时间，命中当帧可能只剩零点几秒。取 0.1 秒而不是 0，是为了排除"刚恢复视力"的边界，同时不会把"闪到一半"的击杀漏掉。

## line-up impact 的基准

直接用"该线位的回合胜率"排序会奖励强队的每一套道具。所以减去**同队同侧的基准胜率**：

```
impact = win_rate(lineup) − win_rate(team, side)
```

单位是百分点，正数表示这套道具的使用场景比该队该侧的平均水平更容易赢。样本仍然很小（一场 dust2 只有十几条 ≥3 次的线位），因此 UI 把收益与使用次数放在同一行，让读者自己判断置信度；不做显著性检验，也不把它写进选手评分。

## 已知取舍

- 回合归属用 `WinnerTeamKey`，平局/数据缺失的回合不计入分子但计入分母（保守）。
- 一条线位可能被同一回合多次投掷，`rounds` 去重，`wins` 也按回合去重。
