# 设计

## 决策

**为什么遍历全部已解析比赛而不是当前选中场次**：徽章出现在每张卡片上，用户点"刷新封禁"的意图是"把资料库里的封禁状态更新一遍"。逐场刷新会让人点 30 次。

**为什么 Key 走 cache/ 而不是 config.json**：与 GCPD Cookie 同理，`config.json` 会被备份/分享；Web API Key 泄露等于他人可用你的配额并关联到你的账号。

**为什么没有 Key 也要跑一次**：`Lookup` 在无 key 时走纯缓存路径，能立刻把"历史上被封"的人标出来；这比直接拒绝更有用，也解释了为什么状态栏会出现 `skipped`。

## 风险

- 分批查询是串行的（`vac.Client.Fetch` 一次最多 100 个 ID），选手数量多时耗时线性增长；本轮加了 90 秒超时上限。
- Steam 返回 403（Key 无效）会原样显示错误文本，不做 Key 有效性预检。
