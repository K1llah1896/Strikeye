# 设计

## 决策

**为什么按标签页逐个扫描而不是直接拼下载 URL**：GCPD 的下载 URL 带一次性 `outcome_id`，无法从分享码推导；只能先列表再匹配 `match_id`。

**为什么扫描顺序用 `gcpd.Tabs` 原序**：Premier 在首位，最常见；命中即返回，平均只扫 1–2 个标签页。

**为什么列表失败要 `continue` 而不是返回错误**：某些标签页对未开通对应模式的账号返回错误页；一个标签页失败不应让整个导入放弃。

**为什么复用 `steamBusy`**：分享码导入与批量下载共用同一条网络通道和状态条，同时进行只会互相覆盖状态；共用标志顺便阻止重复点击。

## 风险

- 分享码对应的比赛若从未在客户端"下载"过，match history 里没有记录，只能报 not found（文案已说明）。
- 每页最多 `MaxPages` 页（默认值），很久以前的比赛可能翻不到。
