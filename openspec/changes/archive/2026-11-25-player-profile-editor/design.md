# 设计

## 决策

**为什么放在选手抽屉而不是资料库卡片**：档案是"这个人怎么打"的注释，编辑时人正看着他的数据（Rating、TTD、残局）；放在卡片上要离开当前视图。

**为什么复用 `profile.Save` 而不是直接 Upsert**：CLI 的语义是"空字段不覆盖旧值、标签为 nil 表示不改"，这是刻意的产品行为（避免误清空）。UI 若直接 Upsert 会把空输入框写成空字符串，两者行为就会分叉。

**为什么草稿要带 SteamID**：`ui.TextInput` 绑定的是字段指针，重新渲染时不会重置文本。若草稿不记录"这份文本属于谁"，展开下一位选手会看到上一位的备注 —— 这也是一个会静默写错人的风险。

## 风险

- 编辑是同步写 SQLite（毫秒级），没有"正在保存"状态；若未来加网络同步需要改成异步。
- 标签输入用逗号拼接，标签本身含逗号会被拆开；`storage.ParseTagList` 支持中英文逗号，与 CLI 一致。
