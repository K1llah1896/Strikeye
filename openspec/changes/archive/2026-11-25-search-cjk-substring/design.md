# 设计

## 决策

**为什么不用 `trigram` 分词器**：FTS5 trigram 需要 ≥3 个字符才能命中，"双架"只有两个汉字，仍然搜不到；而改分词器要重建索引并影响既有拉丁词排序。

**为什么按 `demo_id` 去重而不是 union all**：FTS 与 LIKE 会同时命中同一条（例如查询 `de_dust2`），重复行会让 Library 过滤集看不出问题但结果列表出现重复 demo。

**为什么只在含非 ASCII 时才走 LIKE**：拉丁查询的 FTS 排序（bm25）是主要价值；混入 LIKE 会让"按相关度排序"退化成"按 id 排序"。中文场景 FTS 本来就给不出结果，用顺序可接受。

**为什么 LIKE 只取 `limit` 条**：兜底路径没有排序依据，多取无意义；且 UI 只用命中集做并集过滤。

## 风险

- 中文查询的结果不按相关度排序（按 demo_id 升序）。
- LIKE 扫描是 O(rows)，几千行无感，几十万行需要换 trigram + 前缀补全。
