# Design: 对手倾向报告

## Context

数据面已经齐了：`match_rounds`（侧别、经济类型、装备值、胜者、`bomb_site`）、`match_players`（`team_key`、`spec_slot`）、`match_purchases`（逐件购买、价格表）、`.cs2rpl` 回放（死亡事件含位置）。缺口只是"按队聚合"这一层。

## Decisions

1. **不建新表**：倾向报告是派生视图，口径随分析算法演进（例如以后改 KAST 判据）应随之重算，落库会制造第二份真相。诊断型查询在 2 场 demo（49 回合）上是毫秒级。
2. **队伍→侧别映射用 demo 行**：`teamSides` 只认 `TeamAName`/`TeamBName`（不猜队名变体），命中后该队的每回合侧别直接取 `TeamASide`/`TeamBSide`；队名不匹配则整场跳过，避免把别人的数据算进报告。
3. **下包点只统计本队 T 侧**：A/B 分布回答的是"这队打哪边"，把对手的下包算进来会让 CT 侧的回合污染样本。
4. **开场击杀按 callout**：取每回合最早的一次死亡，若击杀者属于本队则计入；callout 用死者位置（首杀位置比击杀者位置更能说明交火区域），并记录 `FreezeEndTick` 起的秒数。
5. **道具量按本队选手的购买统计**：`match_purchases` 只含库存变化事件，用 `steam_id → team_key` 过滤，避免把对手的烟算进来。
6. **CSV 拉平成 `kind` 列**：分图/侧别/经济/下包/开场五种粒度，列数不同；单表长格式比五个文件更容易被 Excel 透视。
7. **首杀耗时用回合 `freeze_end_tick` 为基准**：热身期 tick 会让首杀显示成 150 秒（此前 bug 已修正，报告沿用同一基准）。

## Risks

- `SpecSlot` 为空的历史行会漏掉首杀归属（旧解析结果），重解析即可修复。
- 经济类型为空的历史行归入 `unknown` 桶，报告仍完整但提示数据陈旧。
