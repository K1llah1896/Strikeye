# 设计

## 决策

**为什么按"不同颜色数"判定而不是比对像素**：字体渲染与布局会随平台字体度量变化，金样比对必然脆；"渲染出至少 N 种颜色"能稳定抓住"整页空白/直接 panic/只画了背景"这三类真实故障。

**为什么每个标签页单独渲染一次**：切页分支里有大量 `switch case`，只渲染默认页会漏掉其余分支；八个页面 0.4 秒，值得。

**为什么用 `t.Cleanup` 关库**：渲染过程中视图可能持有 DB 句柄（后台 goroutine），提前关闭会让少数用例偶发失败。

## 风险

- 覆盖的是"不崩 + 有内容"，不覆盖交互正确性（点击后状态变化仍靠单测）。
- 渲染依赖字体存在与否；缺字体时颜色数可能偏低，阈值取 30–60 留了余量。
