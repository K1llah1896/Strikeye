# 语音分轨与偏移修正

## 为什么

内置 Opus 解码落地后发现两个问题，都属于"数据有了但用不对"：

1. **偏移被截断**：`.cs2voice` 帧头把 `uncompressed_sample_offset` 存成 `uint16`，最多 65535 个样本（48kHz 下 1.37 秒）。真实语音一句超过 1.37 秒就会回绕，时间线错乱——用 72000 的偏移实测读回 6464。
2. **只有混合单轨**：一条混合轨能听，但要单独听某个人的报点、或者只想保留 IGL 的指挥，就必须分轨。

## 变什么

1. 容器升到 **v2**：帧头偏移字段 `uint16` → `uint32`（31 → 33 字节），读取仍兼容 v1。
2. `DecodeOpusDir` 输出 `speaker_<xuid>.wav`（每人一条）+ `mixed.wav`（混合），并按偏移补静音，使每条轨与 demo 时间线对齐。
3. `voice-decode` 的 JSON 增加 `tracks`（每个说话人的文件、时长、帧数）。

## 影响

- capability：`voice-capture`，只新增 requirement。
- 旧 `.cs2voice`（v1）仍可读；新写入一律 v2。
- 分轨时序修正后，同一句跨 1.37 秒的语音不再错位——这是 v1 容器的正确性缺陷，不只是精度问题。
